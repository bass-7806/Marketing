# คลิปเอาชีวิตรอดภาษาไทย (ซีรีส์)

สกิลนี้ทำคลิปแอนิเมชันแนวตั้ง ~68 วินาที เล่าแบบบุรุษที่สอง ("ถ้าคุณ…") ผสมความรู้เอาชีวิตรอดจริงกับเรื่องลุ้นที่จบด้วยหักมุม แล้วต่อเป็นซีรีส์หลายตอน
ทุกอย่างทำในเครื่อง ยกเว้นเสียงพากย์ (อีเลฟเว่นแลบส์)

ตัวอย่างที่ทำเสร็จแล้วทั้งตอน: `examples/flood-ep1/` (ซีรีส์น้ำท่วมหมู่บ้าน ตอนที่ 1) — ดูก่อนทำตอนแรก

## ไฟล์อ้างอิง (อ่านเมื่อถึงขั้นที่ใช้)
| ไฟล์ | อ่านตอน |
|---|---|
| `references/story-formula.md` | วางซีรีส์ เขียนบท เขียนบทเสียง แผนซับ |
| `references/style-bible.md` | วางช็อต วาดฉาก (คลังชิ้นส่วน + พื้นที่บนจอ + ข้อผิดพลาดที่เคยเจอ) |
| `references/production-stack.md` | ติดตั้ง เสียงพากย์ ดนตรี เสียงประกอบ เรนเดอร์ |
| `references/channel-analysis.md` | ข้อมูลวิจัยช่องต้นแบบ (ตัวเลขวิว โครงซีรีส์) |

นอกจากนี้ต้องโหลดสกิล `/hyperframes` ก่อนเขียนหรือแก้ไฟล์คลิป — มีกติกาการเรนเดอร์ที่ต้องทำตาม

## ภาษา
- **คุยกับผู้ใช้เป็นภาษาไทยทุกข้อความ** ตลอดการทำงาน รวมถึงรายงานความคืบหน้า คำถาม สรุปผล และข้อผิดพลาด — ผู้ใช้สกิลนี้ส่วนใหญ่เป็นครีเอเตอร์ไทยที่อาจไม่ถนัดภาษาอังกฤษ ถ้าผู้ใช้พิมพ์มาเป็นภาษาอื่นตลอด ให้ตอบเป็นภาษานั้นแทน
- อธิบายแบบภาษาคนทั่วไป เลี่ยงศัพท์เทคนิค (เช่น พูดว่า "ไฟล์เสียง" แทน "asset", "ตรวจงาน" แทน "lint") ถ้าจำเป็นต้องใช้ศัพท์อังกฤษ ให้อธิบายสั้นๆ ครั้งแรกที่ใช้
- เอกสารทำงานเป็น **ภาษาไทยทั้งหมด** — บท สเปก บันทึกตรวจงาน หัวข้อ ป้ายกำกับ (ยกเว้นชื่อไฟล์ โค้ด และตัวย่อที่เลี่ยงไม่ได้)

## โครงโฟลเดอร์
```
<โฟลเดอร์งาน>/
  <ซีรีส์>/series-bible.md        ← ตัวละคร แผน 3 ตอน ทะเบียนเบาะแส (ใช้ร่วมทุกตอน)
  <ซีรีส์>-ep<N>/
    script.md                      ← บทภาษาไทย + แหล่งข้อมูล
    vo_text.txt                    ← บทสำหรับเสียง (ตัวเลขเป็นคำอ่าน + แท็ก)
    captions_plan.json             ← แผนซับ
    shots.py                       ← รายการช็อต (วาดฉาก)
    audio/                         ← vo_raw.mp3, vo_alignment.json, vo.wav, captions.json, music/
    video/                         ← โปรเจกต์ไฮเปอร์เฟรมส์ (SPEC.md, audio_cues.json, assets/, compositions/)
    <ซีรีส์>-ep<N>.mp4             ← ไฟล์สุดท้าย
```
ด้านล่าง `$SKILL` = โฟลเดอร์ของสกิลนี้

## ขั้นตอน

### 0. ตรวจเครื่อง (ครั้งแรกในเครื่องนั้น)
ตรวจตามตารางใน `production-stack.md` บอกผู้ใช้เฉพาะสิ่งที่ขาด พร้อมวิธีแก้ โปรแกรมที่ขาด (ffmpeg, uv ฯลฯ) เสนอติดตั้งให้ได้

**คีย์อีเลฟเว่นแลบส์** — ผู้ใช้หลายคนมาจากโพสต์ที่ไม่ได้อธิบายเรื่องคีย์ ถามก่อนว่ามีบัญชีอีเลฟเว่นแลบส์หรือยัง แล้วพาทำทีละขั้น:
0. **ยังไม่มีบัญชี**: ให้สมัครที่ elevenlabs.io (ปุ่ม Sign up ใช้อีเมลหรือบัญชี Google ได้) แพ็กฟรีพอสำหรับทดลอง ราว 5–6 ตอนต่อเดือน บอกด้วยว่าแพ็กฟรีไม่ครอบคลุมการใช้เชิงพาณิชย์ ถ้าจะทำช่องหารายได้ควรใช้แพ็ก Starter ขึ้นไป — ผู้ใช้สมัครเอง ผู้ช่วยไม่สร้างบัญชีแทน
1. บอกวิธีสร้างคีย์: elevenlabs.io → Developers → API Keys → สร้างคีย์ เปิดสิทธิ์ **Text to Speech** และ **Voices: Read**
2. สร้างไฟล์ `.env` ในโฟลเดอร์งานให้ โดยมีบรรทัดเดียว `ELEVENLABS_API_KEY=` (ยังไม่มีค่า) แล้วเปิดไฟล์ให้ผู้ใช้วางคีย์ต่อท้ายเอง และบอกว่าไฟล์ชื่อขึ้นต้นด้วยจุดจะซ่อนใน Finder (กด Cmd + Shift + . เพื่อแสดง)
3. **อย่าขอให้ผู้ใช้วางคีย์ในแชต** ถ้าผู้ใช้วางมาแล้ว ให้นำไปใส่ `.env` แทนการใช้จากแชต อย่าพิมพ์คีย์ซ้ำ และแนะนำให้สร้างคีย์ใหม่แทนคีย์ที่หลุดในแชต
4. ตรวจว่าคีย์ใช้ได้ด้วยการสร้างเสียงสั้นๆ ตอนถึงขั้นที่ 3 ไม่ต้องอ่านหรือแสดงค่าคีย์
5. **ไม่อยากสมัคร หรืออยากลองก่อน**: บนแมคใช้เสียงไทย Kanya ที่มากับเครื่องได้ฟรี (`say -v Kanya`) แต่เสียงแข็งเหมือนแอปนำทาง ไม่ลุ้น บอกผู้ใช้ตรงๆ ว่าเหมาะแค่ทดลองทำคลิปแรก วิธีใช้อยู่ใน `production-stack.md` หัวข้อเสียงพากย์

### 1. วางซีรีส์ (ตอนแรกของซีรีส์เท่านั้น)
ถามผู้ใช้แค่ "ภัยอะไร ที่ไหน กับสัตว์อะไร" ถ้ายังไม่บอก ให้เสนอ 3–5 ไอเดียที่ใกล้ตัวคนไทย จากนั้นเขียน `series-bible.md` ตาม `story-formula.md` §1

### 2. เขียนบท
- เขียน `script.md` ตามโครง 5 ท่อน (`story-formula.md` §2) พร้อมเวลาโดยประมาณ และการ์ดบนจอที่จะใช้
- **ค้นเว็บยืนยันทุกตัวเลข** แล้วใส่ "แหล่งที่มาของข้อเท็จจริง" ท้ายบท แจ้งผู้ใช้ถ้าต้องเปลี่ยนตัวเลขจากที่ตั้งใจ
- เขียน `vo_text.txt` (§6) นับตัวอักษรให้อยู่ราว 560–620 (§5)
- **ส่งบทให้ผู้ใช้อนุมัติก่อนสร้างเสียง** — เสียงกินเครดิต (~1,000 ต่อตอน) และแพ็กฟรีมีจำกัด

### 3. สร้างเสียงพากย์
```bash
python3 $SKILL/scripts/tts_elevenlabs.py vo_text.txt audio --env-file <ไฟล์ .env ที่มีคีย์>
```
- **ไม่มีคีย์ แต่มี ElevenLabs connector ในเซสชัน**: สร้างเสียงด้วย `creative_generate_speech` (เสียงจอร์จ) ดาวน์โหลดเป็น `audio/vo_raw.mp3` แปลงเป็น `audio/vo.wav` (48 kHz สเตอริโอ) แล้วทำเวลาคำด้วย `npx hyperframes transcribe --model small --language th` แทน `vo_alignment.json` — แจ้งผู้ใช้ก่อนเพราะใช้เครดิต
- ค่าเริ่มต้นคือเสียงที่ผู้ใช้เลือกแล้ว (จอร์จ v3, ความเร็ว 1.0) เปลี่ยนด้วย `--voice --model --speed`
- ความยาวเป้าหมาย 60–70 วินาที ถ้าเกิน 72 → ตัดบทแล้วสร้างใหม่ (**อย่าเร่งความเร็วหรือตัดช่วงเงียบ** — ผู้ใช้ทดสอบแล้วว่าทำให้เสียความลุ้น)
- ส่ง `audio/vo_raw.mp3` ให้ผู้ใช้ฟัง ระหว่างนั้นทำขั้นต่อไปได้เลย

### 4. ซับ
เขียน `captions_plan.json` (`story-formula.md` §7) แล้ว:
```bash
python3 $SKILL/scripts/caption_groups.py audio/vo_alignment.json captions_plan.json audio/captions.json
```
ผลลัพธ์บอกเวลาเข้า–ออกของทุกวลี ใช้เวลาเหล่านี้กำหนดจุดตัดช็อตในขั้นต่อไป

### 5. เริ่มดนตรี (รันเบื้องหลังทันที เพราะใช้เวลานาน)
```bash
cd audio && mkdir -p music && nohup uv run --python 3.12 --with "transformers<5" --with torch --with soundfile --with numpy --with scipy \
  python $SKILL/scripts/musicgen_bed.py "<คำอธิบายดนตรี>" <ความยาวคลิป> music/bed.wav 7 > music/musicgen.log 2>&1 &
```
คำอธิบายและข้อควรระวังเรื่องแรม: `production-stack.md`

### 6. สเปกและช็อต
- สร้างโปรเจกต์: `npx hyperframes init video --example blank --resolution portrait --non-interactive --skip-skills --skill hyperframes`
- เขียน `video/SPEC.md` (ภาษาไทย): เป้าหมาย ความยาว สี ตัวอักษร และ **ตารางช็อต** — ช็อตละ 3–7 วินาที ตัดตรงจุดเริ่มวลีใน `captions.json` แต่ละช็อตระบุภาพ การเคลื่อนไหวหลัก และเสียงประกอบ (ดู `examples/flood-ep1/SPEC.md`)
- เขียน `shots.py`: เรียก `scene(id, start, dur, svg, overlay, js, origin=, push=)` ทีละช็อต แล้วปิดด้วย `build(ความยาวรวม)` — ใช้ชิ้นส่วนจาก `lib_draw.py`, ของใหม่ให้เพิ่มเข้า `lib_draw.py` (ดู `style-bible.md`)
- คัดลอกเสียง: `video/assets/audio/vo.wav`, `video/assets/sfx/` จาก `$SKILL/assets/sfx/`
- คัดลอกฟอนต์: `$SKILL/assets/fonts/Kanit-*.ttf` → `video/assets/fonts/` (เครื่องที่ไม่ใช่แมคใช้ Kanit แทน Sukhumvit Set อัตโนมัติ — ถ้าโฟลเดอร์ fonts ว่าง ดาวน์โหลดจาก `https://raw.githubusercontent.com/google/fonts/main/ofl/kanit/Kanit-{Medium,Bold}.ttf`, OFL)
- เขียน `video/audio_cues.json` (เสียงพากย์, ดนตรี + automation, ฝน, เสียงประกอบ — ตัวอย่างใน examples)
- สร้างไฟล์คลิป:
```bash
python3 $SKILL/scripts/build.py shots.py video audio/captions.json
```

### 7. ตรวจ
```bash
cd video && npx hyperframes check --json        # แก้ทุก error ชั่งทุก warning
npx hyperframes snapshot --review               # อ่านแผ่นรวมภาพทุกแผ่น รวมแผ่นจอมือถือ
```
ดูภาพจริงทุกครั้ง — การตรวจผ่านไม่ได้แปลว่าสวย สิ่งที่ต้องดู: หู/หาง/วงกระเพื่อมอยู่ถูกที่ไหม, ซับทับของสำคัญไหม, ตัวอักษรอยู่ในพื้นที่ปลอดภัยไหม, อ่านภาพออกไหมโดยไม่ต้องอธิบาย แก้แล้วถ่ายเฉพาะจุดที่แก้ (`snapshot --at`)

### 8. ใส่ดนตรี พรีวิว เรนเดอร์
- เมื่อ `music/bed.wav` เสร็จ: ตรวจว่ามีเสียง (`ffmpeg -i bed.wav -af ebur128 -f null -`) คัดลอกเข้า `video/assets/audio/` เพิ่มใน audio_cues แล้ว build ใหม่
- เปิดพรีวิวให้ผู้ใช้แก้เองได้: `npx hyperframes preview --background` (บอกลิงก์ localhost)
- เรนเดอร์: `npx hyperframes render -o ../render.mp4 --workers 2` แล้ว `bash $SKILL/scripts/finalize.sh ../render.mp4 ../<ซีรีส์>-ep<N>.mp4`
- เขียน `video/REVIEW.md` (ภาษาไทย): สิ่งที่ตัดสินใจเอง สิ่งที่วัด/ไม่ได้ฟัง ช็อตที่อ่อนที่สุด เครดิตเสียง
- ส่งไฟล์ให้ผู้ใช้ พร้อมบอกตรงๆ ว่า **เสียงวัดแล้วแต่ไม่ได้ฟัง** ให้ผู้ใช้ฟังเช็กดนตรี เวลาซับ และความดังเสียงประกอบ

### 9. หลังจบตอน
อัปเดต `series-bible.md` (เบาะแสที่ฝังแล้ว/เฉลยแล้ว, ประโยคเปิดตอนถัดไป) แล้วเสนอเขียนตอนถัดไปทันที — ซีรีส์แนวนี้ต้องลงตอนต่อภายใน 1–2 วัน
